# Papermoon 单人人工测试

源码启动器使用电脑现有的Python 3.10或更新版本，请保留整个Papermoon源码目录。
SkillEditorClient beta 0.1.exe自带Python/Tkinter，可独立复制和运行。首次试用可以直接启动Core，
无需先打开编辑器。

## SkillEditorClient 表单试验版

双击根目录 **SkillEditorClient beta 0.1.exe**，无需安装Python，不会保留后台CMD。
源码可通过`Start_SkillEditorClient.vbs`启动，修改条目仍需手动保存。
exe以自身所在文件夹为基准读取userdata/catalog.json；独立复制exe时，如需已有自定义
技能请同时复制此内容文件。exe内的Core测试也可独立运行，点击测试时才会打开交互终端。
修改Python源码后需重新打包exe，修改内容项目不需要。
当前beta 0.1 exe已包含calculation字段统一，旧operation字段不再接受。
版本号显示在窗口标题和Windows文件属性中，数字文件版本为0.1.0.0。

以下是当前源码界面流程（在beta 0.1打包后调整）：

1. 左下选择“固有技能”，点击“新建”，填写名称和Rank，点击“开始”；点击“取消”返回。
   新建固有技能ID从10开始，在最大已有数字编号后顺延；0至9保留测试使用。
   ID在JSON中为字符串，例如`"10"`，角色引用也填写`"10"`；既有ID不会自动改写。
2. 新技能初始没有技能单元。名称和Rank为11pt，可继续编辑，文本框约为原宽度一半；
   说明使用原10pt常显多行文本框，顶部不再重复显示名称/Rank摘要。
   Rank下拉不列GM，但手动输入GM可以校验、保存。
3. 点击加大的11pt“新建技能单元”，再展开该单元。新单元component_id从unit_0起自动生成，无需输入；
   既有单元ID保留。新单元的技能类型和目标初始留空，提示“选择技能类型”“选择效果目标”；
   选择后显示对应说明。可用阶段在灰色框内以中文选项勾选，内部仍保存AP1等规则键。
4. 展开cost，选择resource并填写数字value；可添加多项消耗或删除无需支付的消耗。
   当阶段不包含AP1/AP2时，action_point不出现在候选中。移除AP阶段会清空已选AP资源，
   需重新选择资源或明确删除这条消耗，数值不自动改变。
5. 展开effects，点击“新建效果”，再展开该效果，从effect_type下拉选择效果，下面会显示中文名称。
   未选择合法效果类型时不显示effect_data区域；清空类型会隐藏参数，再次选择时保留已有参数草稿。
   在effect_data的“参数选择”中选择字段并点击“添加参数”，再填写值；星号表示固定必填项。
   布尔值可选true/false，伤害类型等固定取值可下拉选择；status_id包含当前项目的自定义状态。
   资源运算、成长、事件修改、顺序调整、伤害/消耗调整及资源回复的方式统一在calculation中选择。
   数值直接填数字，文本直接填写；列表和嵌套对象可切换“效果参数高级设置”。两种方式同步同一份内容，
   草稿不合法时会保留内容并阻止切换。切换effect_type不删除旧内容，不适用字段可点击“删除”。
   持续时间、正负面等效果顶层字段仍保留在“效果高级设置”中；切换成即时效果后如不适用需自行清理。
6. 点击“校验”后“保存条目”，或使用Ctrl+S。component_id为空或重复、参数不合法时不能保存。

技能说明常显，其余折叠区默认关闭。技能单元、消耗、效果可添加/删除多条；折叠不删除内容。
从左侧选择已有技能时同样全部折叠；重复选择当前技能也会收起，未保存或未完成的草稿不被重载。
单元标题、加号和“删除此技能单元”按钮均为11pt，与新建按钮一致。
删除按钮位于各单元末尾，只删除它所在的单元；不再使用全局删除按钮和单元选择框。
删除最后一个展开的单元后，容器高度与滚动范围立即收缩，不需重新添加来恢复显示。
现有技能的条件、次数限制、咏唱、触发等字段保留在相应“高级设置”中，不会因表单保存丢失。
“JSON预览（只读）”页签提供完整预览，顶部重复按钮已移除；未保存草稿可在切换条目或关闭时选择“否”放弃。
左侧目录和职介技能仍沿用原版方式；其他类型专用字段暂未新增表单。

单元内效果区在消耗区之前。未选效果类型时只提示“请选择效果类型”；参数区使用与阶段区一致的灰色背景。
阶段选项文字修改SkillEditorClient/model.py的PHASE_LABELS右侧值，保留左侧AP1/AP2等内部键；
消耗区下方提示修改SkillEditorClient/forms.py的COST_HINT。

例如直接伤害：新增一个空效果，effect_type选择damage，添加damage_type并选magic，
再添加value并填30，即表示30点基础魔术伤害。完整合法性以校验提示及效果字典为准。

需要查阅时，点击顶部“效果字典”，或点击某条效果旁的“查看说明”。独立窗口按类型列出
effect_data固定必填/可选参数、候选值和效果字典说明，持续效果附带顶层公共字段说明。
顶部支持搜索类型、中文名称、参数及说明文字。窗口只读，可选中文字按Ctrl+C复制；
可与编辑窗口同时使用，关闭它不会改动项目，也不会丢弃或保存草稿。

源码版的参考窗口和完整字典页签读取`SkillEditorClient/effect_dictionary.txt`。
可修改这份展示文本，保存后重新启动源码版查看；保留效果标题便于按类型定位说明。
开发规范另存于`game/skill/代码数据规范.txt`；两份内容不自动同步。
beta 0.1 exe内置打包时的客户端展示字典；之后修改外部文本不会自动更新exe内部资源。

## 启动Core

双击根目录的 **Start_Core.cmd**。

- 选择 **1**：两组已录入的御主和尼禄在中央广场直接开战，适合先测试战斗。
- 选择 **2**：两组主从分别从住宅区、教会出发，测试移动、相遇、地图行动和战斗衔接。
- 选择 **3**：分别更换A、B两方的御主卡和从者卡，包括编辑器保存的新卡。
- 选择 **4**：运行原有基础场景，使用通用测试角色。
- 选择 **0**：关闭启动菜单。

你独自依次操作双方所有角色，程序不会替对手选择。两组镜像卡使用原始卡面数值，
只在角色名称前加A/B方标记。测试场景使用简化的三地点地图，圣杯在首名从者死亡后
出现并就绪，默认上限120回合；这些是测试场景设置，不修改卡片或通用规则。

菜单按编号或显示的完整名称输入；数字输入窗口则输入要求范围内的整数。
相同敏捷的角色可能重掷先手，这是正常规则。

## 测试时可用的辅助指令

| 指令 | 用途 |
| --- | --- |
| `help` | 查看辅助与GM指令 |
| `status` | 查看当前角色的基础状态 |
| `status all` | 查看所有存活角色的基础状态 |
| `position` | 查看当前角色位置和场地 |
| `map` | 查看当前位置及相邻节点 |
| `grail` | 查看圣杯状态 |
| `commandspell` | 打开令咒菜单 |
| `quit` | 结束本次测试并保存记录 |

此入口用于你兼任双方与GM的本地测试。`status all`不会隐藏对手状态；正式玩家的
信息过滤仍由既有Session接口负责。技能、目标、反应和保命选择均沿用现有终端流程。
终端当前显示方式保留，后续可按试用反馈逐项修改。

GM指令格式见`help`。角色名较长时可复制名称，包含空格的名称要使用双引号；
不要将A/B标记省略，以免指定到错误角色。

## SkillEditorClient高级JSON设置

双击根目录的 **Start_SkillEditorClient.vbs**，打开当前技能编辑器；复杂结构可在“条目高级设置”中编辑JSON。

1. 左侧按类别浏览或搜索已有技能、魔术、宝具及角色卡；右侧编辑完整定义。
2. **复制为新条目**可以基于现有定义创建变体；**新建**提供六种可校验模板，包含职介技能。
3. **校验**检查当前草稿和整个项目引用，但不保存；**保存条目**校验通过后保存。
4. **效果字典与格式参考**页提供现有规范。
5. **导入条目 / 导出条目**交换单个JSON条目；**打开项目**切换整份内容项目。
6. **恢复内置 / 删除自定义条目**撤销对应覆盖。仍被角色卡引用的自定义技能不能删除。
7. **技能测试**用当前已保存项目打开独立的技能测试终端。

这一版是完整定义的JSON编辑器，尚未把44个效果的每个字段制作成表单。
编辑器负责数据编辑和调用校验器，全部结算由Core复用原规则。

职介技能：左下选择**职介技能**后新建，输入的名称就是角色卡引用名称，可以使用
中文，无需user_前缀。右侧的`ranks`分别定义C、B、A等等级，每个等级是一份完整
组件列表；不会自动推导其他等级。默认模板提供C级、常驻攻击力+5。保存后，在角色卡
的`class_skills`中添加名称与等级，例如：

```json
"class_skills": [{"name": "自定义职介技能", "rank": "C"}]
```

引用的名称与等级必须已经定义。仍被角色卡引用的自定义职介技能及等级不能删除。
内置职介技能也可编辑或复制，恢复内置会撤销本地覆盖。原有四目录项目能直接打开，
读取时在内存中补齐新目录，点击保存时才写回，并保留原文件备份。

Windows启动时启用高DPI适配，使文字按原生分辨率渲染。保留最初的字体与字号：
JSON区Consolas 11、参考区微软雅黑UI 10，其余界面使用系统默认字体；不增加文本
行间距，列表保持原始逻辑行高。更新后需关闭并重新打开编辑器，已打开的窗口
不会自动切换显示模式；需要保留的草稿请先保存。

新技能保存后，需要把它的ID加入角色卡的相应内容列表，再在Core菜单3选择该卡。
宝具需赋给从者，且仍受宝具数量上限限制。基础魔术在角色卡中引用目录ID（例如
`healing`），其定义内部的skill_id为`basic_magic:healing`。

默认改动写入 **userdata/catalog.json**；内置Python数据及原始样本不被覆盖。
每次覆盖项目文件前保留上一版为`catalog.json.bak`。修改在下一次启动Core时生效，
不会影响已开始的那局游戏。要恢复全部内置内容，可在关闭编辑器后把该文件移开。
同时打开两个编辑器时，后保存者若发现文件已改变会拒绝覆盖，需重新打开项目。

## 测试记录和反馈

每次开始游戏，Core都会在 **userdata/runs/日期时间-标识/** 下保存：

- `terminal.txt`：终端输出与输入，便于定位你看到的提示。
- `reports.jsonl`：逐条刷新写入的完整GM战报，异常中断时可保留已完成部分。
- `reports.json`：结束时汇总的战报。
- `summary.json`：场景、随机种子、结束原因和最终角色详细状态。
- `catalog.json`：本次实际使用的完整内容快照。
- `error.txt`：发生程序异常时的堆栈。

正常退出用`quit`；Ctrl+C也会保存记录。直接关闭终端窗口无法保证完成最终汇总，
但已刷新的逐条战报和终端记录会保留。结束后启动器会等待按键，方便阅读最后提示。

反馈时告诉我：当时的角色、阶段、输入和期望看到的信息，以及对应测试记录目录。
涉及终端展示时，我会调整展示层，保持结算规则由Core统一处理。

python -m core --scenario battle --seed 20261021
python -m core --scenario map

规则模块导入现统一为`game.*`。目录整理后请重新打开正在运行的Core或编辑器，
需要保留的编辑草稿先保存。userdata项目及测试记录位置不变。


## 状态仓库人工检查

- 当前项目必须使用format_version=2，并包含status目录；不自动迁移旧项目。
- 在Skill Editor的新建类型中选择“状态”，填写唯一status_id，修改触发效果与持续时间并保存。
- 可直接查看内置burning，复制为新状态后再编辑；保存、导入导出、恢复内置和删除均沿用现有操作。
- 在技能effects中使用 `{"effect_type":"add_status","effect_data":{"status_id":"burning"}}`。
- 不需要在目标角色卡上装燃烧结算技能；重启Core后加载保存的状态定义。
- 对同一目标用不同角色施加燃烧，status应分别显示来源；每个来源每次回合末各结算一次。
- 同一来源重复施加，1/2/3层分别造成10/20/30点基础魔术伤害，默认最多3层并刷新持续时间。
- 三次回合末后燃烧到期；净化一条来源不应移除另一条，全部净化后停止伤害。
- 反应型状态每角色每状态每全局回合最多一次，重复施加不应恢复本回合次数。
- 状态被其他条目引用时禁止删除；仓库引用未知status_id、旧value写法应校验失败。
- burning的每层10点魔术伤害、上限3层与3回合只是仓库示例，可在编辑器修改。
- 在状态的伤害effect_data中设置value_source="status_stack_count"、multiplier=每层伤害，
  可另设flat固定加值；不要同时填写value。修改stacking.max_stacks控制上限，保存后重启Core。
- 不同来源各自计算层数，例如A施加2层、B施加1层，应分别结算20与10点基础伤害。
